SUGESTÕES DE MELHORIA – AUTOMATED VIDEO GENERATOR

1. PRIORIZAR MODO PRODUÇÃO PARA VÍDEOS LONGOS
---------------------------------------------
- Objetivo: gerar vídeos longos com a duração completa da narração, não apenas prévias.
- Situação atual:
  - Em src/generators/longs_generator.py existe a flag DEBUG_PREVIEW = True.
  - Enquanto estiver True, todos os vídeos longos são limitados a 30 segundos, cortando texto e legendas.
- Sugestão:
  - Para produção, definir DEBUG_PREVIEW = False (ou remover completamente o bloco de preview).
  - Se quiser manter o modo de teste, transformar em parâmetro de linha de comando (ex.: --preview) ou variável de ambiente.

2. DEFINIR UM FLUXO OFICIAL PADRÃO
----------------------------------
- Objetivo: evitar confusão entre scripts antigos e novos, e reduzir erros humanos.
- Fluxo recomendado, sempre que for gerar uma leva de vídeos:
  1) Validar planilha:
     - Comando: python scripts/validate_roteiro.py
     - Garante colunas obrigatórias, textos mínimos, idiomas válidos e imagens existentes.
  2) Gerar Shorts:
     - Comando: python src/generators/shorts_generator.py
     - Opcional: passar índices específicos via linha de comando para gerar apenas alguns vídeos.
  3) Verificar falhas de TTS/áudio dos Shorts:
     - Comando: python scripts/verificar_falhas.py
     - O script mostra quais Shorts falharam e já imprime um comando pronto para reprocessá-los.
  4) Gerar Longos:
     - Comando: python src/generators/longs_generator.py

- Benefício:
  - Você passa a ter um “ritual” confiável: validar → gerar shorts → corrigir falhas → gerar longos.

3. TRATAR A PASTA "VIDEO_GENERATOR - BASE" COMO LABORATÓRIO/LEGADO
------------------------------------------------------------------
- Objetivo: evitar misturar scripts antigos com o fluxo moderno baseado em src/ e Roteiro_Geral.xlsx.
- Situação atual:
  - A pasta "video_generator - base" contém:
    - Protótipos de Shorts e Longos com planilhas separadas.
    - Scripts de teste (gerador_zoom, gerador_shorts_lote, setup_roteiro, etc.).
  - O código oficial e mais robusto está em src/, usando a planilha única Roteiro_Geral.xlsx.
- Sugestão:
  - Tratar "video_generator - base" apenas como histórico/arquivo de referência.
  - Para produção, usar sempre:
    - src/generators/shorts_generator.py
    - src/generators/longs_generator.py
    - scripts/validate_roteiro.py
    - scripts/verificar_falhas.py

4. CONTROLAR DURAÇÃO DOS LONGOS POR PERFIL DE VÍDEO
---------------------------------------------------
- Objetivo: ter formatos claros (3 min, 7 min, 12 min, etc.) sem precisar editar o texto.
- Situação atual:
  - A duração dos longos é basicamente "duração da narração + paddings" (ou 30s em modo preview).
  - Textos muito longos podem gerar vídeos muito extensos.
- Ideia:
  - Adicionar coluna na aba "Longos", por exemplo:
    - "DuracaoAlvo" (em segundos) ou
    - "TipoVideo" com valores como CURTO/MEDIO/LONGO.
  - Dentro de src/generators/longs_generator.py:
    - Calcular a duração final como:
      - min(duracao_audio + paddings, DuracaoAlvo) quando essa coluna vier preenchida.
- Benefício:
  - Você ajusta o “formato” do vídeo por planilha, sem mexer no código e sem precisar cortar o texto.

5. CENTRALIZAR VELOCIDADE DE FALA POR IDIOMA
--------------------------------------------
- Objetivo: facilitar tunar a naturalidade da voz em EN/ES/PT em um único lugar.
- Situação atual:
  - Config global em src/configs/settings.py:
    - VOICE_RATE = "-10%".
  - Nos Shorts, há exceção manual:
    - Para ES, rate = "+0%".
- Sugestão:
  - No settings.py, definir um dicionário, por exemplo:
    - VOICE_RATE_BY_LANG = {"EN": "-10%", "ES": "+0%", "PT": "-10%"}.
  - Nos generators (Shorts e Longos), ao invés de hardcode:
    - Buscar SEMPRE o rate a partir desse map, com fallback para VOICE_RATE.
- Benefício:
  - Se você decidir que em PT quer um pouco mais lento ou mais rápido, basta mudar em um único ponto.

6. LIMPAR E SIMPLIFICAR O SCRIPT DE DEBUG DOS LONGOS
----------------------------------------------------
- Objetivo: evitar confusão de paths e deixar o diagnóstico mais confiável.
- Situação atual:
  - src/debug_longos.py ajusta o sys.path de uma forma que pode apontar para src/src.
  - Ele tem fallback para caminhos relativos (Roteiros e LONGOS/input_images), o que salva na prática, mas deixa o código menos claro.
- Sugestão:
  - Padronizar o path igual aos generators:
    - Subir dois níveis a partir de src/ e importar src.configs.settings.
  - Manter o comportamento atual de:
    - Listar abas da planilha.
    - Mostrar quantas linhas tem em "Longos".
    - Verificar se há imagens válidas em LONGOS/input_images (e em temas visuais).

7. APROVEITAR MAIS REUSO ENTRE SHORTS E LONGOS
----------------------------------------------
- Objetivo: reduzir duplicação e facilitar a criação de novos formatos (ex.: vídeos quadrados).
- Situação atual:
  - Tanto Shorts quanto Longos:
    - Ajustam tempos de legendas com PADDING_START, PADDING_END e SUBTITLE_OFFSET.
    - Agrupam palavras em blocos para legendas tipo karaokê.
    - Criam CTA visual no final.
  - A lógica é parecida, mas implementada separadamente em cada generator.
- Sugestão:
  - Identificar padrões comuns e extrair funções para src/utils/ (por exemplo, um helper de "criar legendas karaokê").
  - Deixar que Shorts/Longos apenas escolham:
    - Tamanho de fonte.
    - Posições.
    - Cores.
- Benefício:
  - Manutenção mais simples.
  - Facilita criar um terceiro tipo de vídeo com muito menos esforço.

8. TORNAR O COMPORTAMENTO DO TTS AINDA MAIS RESILIENTE
------------------------------------------------------
- Objetivo: evitar gerar muitos vídeos sem voz quando a internet ou o serviço de TTS estiver instável.
- Situação atual:
  - audio_utils.generate_audio_and_word_timings:
    - Faz retry 3 vezes por chunk.
    - Usa fallback de tempos estimados se não conseguir timings exatos.
  - Generators:
    - Se áudio não é gerado ou está vazio, ainda criam vídeo, usando estimativas ou silêncio.
- Sugestões adicionais:
  - Adicionar um contador de falhas consecutivas de TTS:
    - Se ultrapassar um certo limite, abortar o lote com mensagem clara (“sem conexão, tente mais tarde”).
  - Opcional: implementar cache simples dos áudios:
    - Gerar um hash do texto.
    - Se um mp3 com esse hash já existir, reutilizar o áudio em vez de chamar o TTS novamente.

9. ORGANIZAR MELHOR SAÍDAS E TEMPORÁRIOS
----------------------------------------
- Objetivo: manter a pasta do projeto limpa e facilitar achar o que já foi publicado.
- Situação atual:
  - temp_audios/ acumula muitos arquivos mp3 de testes e produções antigas.
  - SHORTS/output_videos_finais/ já tem uma subpasta Concluidos/Publicados, mas ainda há vídeos soltos.
- Sugestão:
  - Manter uma rotina (manual ou script) para:
    - Limpar periodicamente temp_audios/ (seguro, os áudios são sempre regenerados).
    - Mover vídeos gerados para subpastas (Ex.: PENDENTES, PUBLICADOS, ERRO), de acordo com colunas da planilha (StatusPublicacao).
- Benefício:
  - Você enxerga claramente o que falta postar, o que já foi pro ar e o que precisa ser refeito.

10. IMPLEMENTAR O SCRIPT DE COLUNAS PARA PUBLICAÇÃO NO YOUTUBE
--------------------------------------------------------------
- Objetivo: aproximar o projeto da automação completa de publicação no YouTube, como descrito no README.
- Situação atual:
  - O README cita scripts/update_roteiro_shorts_columns.py, mas esse arquivo não existe hoje no repositório.
  - A ideia desse script é:
    - Garantir que as abas "Shorts" e "Longos" tenham colunas como:
      - Plataforma, Publicar, StatusPublicacao, DataPublicacao, HoraPublicacao, GMT,
        TituloShort, DescricaoShort, Hashtags, Privacidade,
        PublicoInfantil, YouTubeVideoId, YouTubeURL.
- Sugestão:
  - Criar esse script em scripts/:
    - Ler Roteiro_Geral.xlsx.
    - Criar/organizar as colunas acima com valores padrão.
  - Ao rodar:
    - python scripts/update_roteiro_shorts_columns.py
    - A planilha fica pronta para, no futuro, alimentar um script de upload via API do YouTube.

11. USAR A PLANILHA COMO CENTRAL MULTIPLATAFORMA
-----------------------------------------------
- Objetivo: planejar YouTube, TikTok e Reels usando o mesmo arquivo.
- Situação atual:
  - A estrutura já é pensada para YouTube (Shorts + Longos).
  - TikTok e Instagram ainda são fluxo semiautomático (upload manual).
- Sugestão:
  - Adicionar colunas simples como:
    - TikTok (SIM/NAO)
    - Reels (SIM/NAO)
  - Utilizar essas flags para decidir:
    - Quais vídeos reaproveitar em cada plataforma.
    - Quais textos (TituloShort, Hashtags) copiar para descrição/caption.

12. MELHORAR O DESIGN DO CTA E DOS TÍTULOS POR CONTEXTO
-------------------------------------------------------
- Objetivo: aumentar retenção e engajamento usando a mesma base de código.
- Situação atual:
  - CTA e títulos já são fortes (fontes grandes, stroke, vinheta).
  - Textos de CTA são fixos por idioma.
- Ideias:
  - Adicionar coluna "TipoCTA" na planilha:
    - Ex.: AMEM, ORACAO, REFLEXAO, PROMESSA.
  - Mapear, no config, diferentes listas de CTA por tipo:
    - Ex.: para AMEM: ["ESCREVA AMÉM SE VOCÊ CRÊ", "COMENTE AMÉM"].
    - para ORACAO: ["VAMOS ORAR JUNTOS", "FIQUE ATÉ O FIM DA ORAÇÃO"].
  - Isso permite testar variações sem mexer no código, apenas mudando a planilha.

RESUMO
------
- Curto prazo:
  - Desativar DEBUG_PREVIEW para longos em modo produção.
  - Seguir sempre o fluxo: validate_roteiro → shorts_generator → verificar_falhas → longs_generator.
  - Tratar "video_generator - base" como laboratório/legado.
- Médio prazo:
  - Controlar duração dos longos pela planilha.
  - Centralizar velocidade de fala por idioma.
  - Melhorar script de debug dos longos e reuso de lógica entre Shorts/Longos.
- Longo prazo:
  - Implementar script de colunas de publicação para YouTube.
  - Usar a planilha como central de multi-plataforma (YouTube, TikTok, Reels).
  - Refinar CTAs e títulos por tipo de conteúdo para maximizar retenção.
